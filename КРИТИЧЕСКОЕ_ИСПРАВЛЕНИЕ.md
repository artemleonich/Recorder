# 🔴 КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ - Thread 1 signal SIGABRT

## Проблема:
Приложение крашилось с ошибкой **Thread 1 signal SIGABRT**

## Причина:
В `RecorderApp.swift` создавалось **ДВА разных экземпляра** `AppSettings`:
1. `@StateObject private var appSettings = AppSettings()` - для environmentObject
2. `let settings = AppSettings()` в init() - для ViewModels

Эти два экземпляра НЕ синхронизировались! Когда SettingsView пытался использовать `@EnvironmentObject var appSettings`, он получал ДРУГОЙ экземпляр, чем тот, который был в `viewModel.settings`.

## Решение:
Создаётся **ОДИН общий экземпляр** `AppSettings` и используется везде:

```swift
init() {
    // Initialize shared settings FIRST
    let sharedSettings = AppSettings()
    _appSettings = StateObject(wrappedValue: sharedSettings)
    
    // ... services ...
    
    // Initialize ViewModels with SHARED settings
    _recordingViewModel = StateObject(wrappedValue: RecordingViewModel(
        settings: sharedSettings  // ← ТОТЖЕ экземпляр
    ))
    
    _notesListViewModel = StateObject(wrappedValue: NotesListViewModel(
        settings: sharedSettings  // ← ТОТЖЕ экземпляр
    ))
    
    _settingsViewModel = StateObject(wrappedValue: SettingsViewModel(
        settings: sharedSettings  // ← ТОТЖЕ экземпляр
    ))
}
```

## Изменённые файлы:

### 1. RecorderApp.swift ✅
- Создаётся один `sharedSettings`
- Используется для инициализации `_appSettings`
- Передаётся во все ViewModels

### 2. SettingsView.swift ✅
- Убран `@EnvironmentObject var appSettings`
- Используется только `viewModel.settings`
- Все `$appSettings` заменены на `$viewModel.settings`
